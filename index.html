New to Local Music Organizer?

Start with the problem, not the technology.

You do not need to learn every tool before using the app. Choose what you are trying to understand, run the relevant check, review the result, and make a change only when you intentionally choose an action.

⌕

I cannot find a file

Health Check finds Music.app records whose local files are missing, inaccessible or suspicious. File Search searches the physical music folders on disk and can reveal the exact file in Finder.

◎

I think I have duplicates

Playlist Duplicates finds repeated entries inside one playlist. Library Duplicates finds multiple Music.app records that may point to the same file. Quality Duplicates compares different physical versions of the same recording.

≡

Where is this track used?

Track Usage and Library Map show which playlists contain a track and where repeated recordings occur. Playlist Compare shows what two playlists share and what is unique to each.

✎

My metadata is a mess

File Maintenance can find repeated spaces and incorrect parenthesis spacing in Music.app Title / Artist / Album and local filenames. Review one row or batch-fix selected issues; safe physical filename renaming verifies the same Music.app track and artwork. Supported tags can also be edited directly, with Undo Last Change.

↻

Music.app shows old file information

Run Library Dashboard in Deep mode. If Music.app still has outdated technical information for a local track, the Music.app info outdated card isolates those files. Refresh Music.app Info asks Music.app to reread the actual audio file without rewriting it.

▣

Artwork is missing

Artwork Check finds tracks without cover artwork. Use the longer live verification when you need to confirm recent Music.app changes rather than relying only on saved index data.

≋

Is this audio really the quality it claims?

Audio Authenticity Analyzer looks for technical signs of lossy-to-lossless conversion, suspicious bandwidth limits, bitrate mismatches and possible sample-rate upscaling. Results are estimates to review, not automatic verdicts.

⌁

I want to inspect one file

Audio Inspector shows codec/container details, bitrate, sample rate, bit depth, channels, duration, file size, an authenticity assessment, a dB-scale spectrogram and raw technical output. The static Inspector does not show a waveform; the interactive full-track waveform belongs to Live Spectrum. Both work without adding the file to Music.app.

⇄

I need to convert or repair audio

Repair / Convert handles common and specialist formats with engines included in the app, plus batch normalization for sample rate and lossless bit depth. After a verified conversion you decide whether to keep the source, move it to Trash or archive it in a dated LMO Backup Folder. Vinyl De-click lets you compare short before-and-after samples before processing a full recording.

⤨

I want a better shuffle

Shuffle Builder creates a new playlist with spacing rules for artists, related projects, albums, repeated titles and covers while leaving the original playlist unchanged.

First five minutes

  1. In Setup, choose the local music folder and report folder and allow Music.app Automation access when macOS asks.
  2. Open Library Dashboard. On the first run, leave Include playlist usage enabled and click Build / Refresh Library Index.
  3. For a quick overview use Standard. Use Deep when you want file-level details such as real lossless bit depth; leave Skip slow file checks off when every available local file must be checked.
  4. Run Audio Quality Dashboard. The category numbers are filters, not automatic error verdicts: click one to see the tracks behind it.
  5. After small additions, removals or replacements, use Refresh Music Changes instead of rebuilding everything.

Know when something can change

  • Dashboards, searches, comparisons and authenticity analysis are diagnostic until you choose an explicit action.
  • Playlist cleanup removes playlist entries, not the physical audio file.
  • Manual tag editing changes supported Music.app fields and provides one-step Undo Last Change.
  • Naming & Tag Formatting scans are read-only. Tag fixes and physical filename renames happen only after explicit review or batch selection; safe filename renames are verified and rolled back if verification fails.
  • Hidden-tag cleanup changes a physical file only after you choose cleanup; the rebuilt file is verified and the original is restored if verification fails.
  • Conversion verifies the new output before the selected original-handling action. Choose Keep original, Move original to Trash or Move original to LMO Backup Folder.
Not using Music.app? Audio Inspector, Live Spectrum, Audio Authenticity analysis, metadata inspection, repair and conversion can also work with individual local files opened from Finder or added by drag and drop.

How to read scan results

  • Found does not automatically mean wrong. Dashboard and scan counters are review filters. For example, 48 kHz, AAC or a lossless file above 16-bit can be perfectly valid.
  • Format and sample-rate cards are there to make a mixed collection understandable. Click ALAC, MP3, AAC, AIFF, WAV, Other audio formats, 44.1 kHz, 48 kHz or >16-bit lossless to inspect the matching tracks.
  • A large hidden-tag count can be normal in a large collection; review the field names and values before selecting cleanup. Web addresses found inside Title or Artist are surfaced for manual review rather than removed automatically.
  • Health Check and Audio Authenticity results are diagnostic evidence, not automatic repair commands.
  • Open representative results in Audio Inspector, Finder or Music.app when you need confirmation.

For very large libraries

  • Build the Library Index first.
  • Let one long scan finish before starting another.
  • Keep external disks connected while a scan depends on them.
  • After small Music.app changes, use Refresh Music Changes instead of rebuilding everything.

Important for large libraries

Build once, then refresh only what changed.

The Library Index is LMO's saved working copy of Music.app information. It lets library-wide tools reuse what has already been read instead of asking Music.app for every record again.

Recent additions, replacements and removals can be refreshed selectively, and a playlist-only change can be indexed without rebuilding every playlist.

Read-only tools use the available saved snapshot and clearly label partial coverage. Use Refresh Music Changes after adding, replacing or removing a few tracks, or Index Selected Playlist after changing one playlist in Music.app.

No mandatory rebuild after relaunch: saved Library Index data is available immediately. On a normal launch, LMO restores the saved SQLite snapshot and applies its small FSEvents physical-change catch-up without launching Music.app. Automatic Library Index also waits until Music.app is already running; explicit user-triggered Music-backed actions such as manual Library Index, Refresh Music Changes or Music.app Diagnostics may launch Music.app when needed. Rebuild the full index only on first use, after a major library change or when the app explicitly reports that verification is required.
Very large libraries: full Music.app records can be ready before every playlist-membership row. LMO labels that playlist usage as partial instead of treating it as complete. Use Index Playlist Usage or Index Selected Playlist to extend coverage; do not clear the Saved Library Index merely because playlist usage is still partial.

Recommended first workflow

  1. In Setup, test Music.app access and choose the primary music folder if needed.
  2. On first use, leave Include playlist usage enabled and click Build / Refresh Library Index.
  3. Use File Search, Library Map, Playlist Compare, Playlist Duplicates and dashboard categories directly from the saved Library Index.
  4. After adding, replacing or removing a few tracks, click Refresh Music Changes.
  5. After changing only one playlist, choose it and use Index Selected Playlist.
Important distinction: the Library Index accelerates Music.app library work. Audio Inspector and Repair / Convert work directly with selected files and do not require a Library Index.
Library Dashboard in plain language

Numbers first, tracks second, changes only when you choose them.

The Dashboard is designed to answer a simple first question: “What is actually in my library?” Run the scan, then select a card to turn a number into a list of tracks you can inspect. The cards do not silently change files.

1

Choose scan depth

Standard is the normal starting point. Deep reads the actual local audio files for more reliable codec, bitrate, duration and lossless bit-depth information. Turn off Skip slow file checks when complete local-file coverage matters more than speed.

2

Understand the category cards

44.1 kHz and 48 kHz are informational sample-rate groups, not errors. ALAC, MP3, AAC, AIFF, WAV and Other audio formats show how the collection is encoded. Select any card to see the tracks behind the number.

3

Fix outdated Music.app file information

In Deep mode, Music.app info outdated appears when Music.app's saved file information does not match the actual local file. Select the card to isolate those tracks, then use Refresh Music.app Info for one track or the whole group. A corrected track disappears from the outdated list after verification.

4

Know what Refresh Music.app Info changes

LMO asks Music.app to reread the existing file and verifies the result. It does not convert, move, delete or rewrite the audio file, and protected tag and artwork fields are checked for unexpected changes. Refresh history is written to the selected log folder when logging is enabled.

5

Review high-resolution files

>16-bit lossless comes from real local-file inspection in Deep mode. It is useful when you want to find 20/24/32-bit lossless or PCM files and decide whether their extra size is useful for your library.

6

Normalize only when you mean to

Batch Normalize can send selected 48 kHz or high-bit-depth results to Repair / Convert. Nothing is normalized merely because it appears in a Dashboard category.

7

Metadata that needs a human decision

LMO can surface web-address text such as www, http or https inside Title or Artist for manual review. It does not automatically cut that text out because it may be part of a legitimate title.

8

Clear Comments without touching audio files

Clear All Comments changes only the Music.app Comments field for the matching records. LMO verifies the live Music.app value, updates the Saved Library Index so an old cache cannot bring the comment back, and keeps Undo data for values that were actually present before the operation. The physical audio files are not renamed or rewritten.

Good default: build the Library Index once, run Standard first, use Deep for file-level questions, and treat every category as evidence to review rather than an instruction to clean.

Built by a collector, for collectors.

I am a music collector and Music.app user with a large offline library accumulated over many years. Eventually it became total disorder: duplicate records, repeated playlist entries, missing artwork, inconsistent tags, broken references, several versions of the same album and rare formats scattered across different folders and disks.

The project began as a small utility for randomizing playlists without changing the originals. As the collection and its practical problems grew, that focused tool expanded into Local Music Organizer: one place to understand the library before touching it, see what was duplicated, learn where a track was used, compare versions and clean safely.

Conversion was another part of the same problem. No single converter handled every difficult source I owned. TAK, SACD ISO, DSD, DTS, AC3, CUE albums, tracker modules and other archival formats often required several tools and a fragile sequence of actions.

The program brought order back to my own collection and solved the practical problems I had lived with for years. Only then did I realize that it could also be useful to other people like me - people who still maintain serious offline music libraries and want control instead of automatic destructive cleanup.

The interface is intentionally restrained and tool-first. Local Music Organizer is not designed as a decorative showcase: screen space is used for evidence, paths, technical details, explicit actions and safety explanations that help solve real library problems.

Live Spectrum, interactive waveform and local player.

Open a physical audio file in an independent macOS player window without creating another Music.app record. The window combines real-time analysis, full-track navigation, transport controls and a cautious gain workflow.

Detailed analysis

  • 512 FFT bands on a logarithmic frequency scale with dBFS markings, peak trace and named frequency regions.
  • Full-track waveform with transient detail and a current-position cursor.
  • Click or drag across the waveform to seek; the lower progress bar is also draggable. After a track reaches the end, drag back and resume from any position.
  • Technical cards report format, resolution, channels, duration, elapsed time, remaining time, progress, peak, RMS, headroom and clipping.
  • Fine, Balanced and Bold presets adjust analyzer density; bar thickness, gap, segmented LEDs, waveform and technical cards can be configured individually.

Transport and independent window

  • Pause keeps the current position. Stop ends playback and returns to 0:00 while keeping the loaded track and waveform. Eject clears the player.
  • The yellow window button minimizes to Dock. The red button hides the window without stopping playback.
  • When the hidden player is still playing, click the Local Music Organizer icon in Dock to restore it.
  • The player and main organizer window remain independent; clicking the player does not intentionally raise the main window.
  • Background conversion and gain processing do not intentionally close the Finder folder containing the source file.

Audio Authenticity Analyzer.

Batch-check the audio behind a local Music.app library without altering the source files. The analyzer compares declared codec, bitrate, sample rate and bit depth with measured spectral behavior, then surfaces only recordings that deserve review.

Library and playlist scanning

  • Scan the saved Music.app Library Index, one selected playlist, or keep the existing single-file drag-and-drop workflow in Audio Inspector.
  • Analyze each physical path once even when the same recording appears in several playlists.
  • Check MP3 and AAC files for obvious disagreement between declared bitrate and observed spectral bandwidth.
  • Check ALAC, FLAC, WAV, AIFF and other lossless files for evidence consistent with an earlier MP3 or AAC source.
  • Check high-resolution files for possible sample-rate upscaling and bit-depth padding.
  • Use distributed short analysis windows across the track so large-library scans remain practical without decoding every file from beginning to end.

Conservative, explainable results

  • No obvious issue means the measured content is broadly consistent with the declared format and is omitted from the detailed report.
  • Review recommended means one or more unusual indicators were found, but the evidence is not decisive and manual inspection is appropriate.
  • Likely authenticity mismatch means a stronger combination of persistent cutoff, transition, occupancy and format-mismatch evidence was detected.
  • Detailed reasoning: every flagged result shows confidence, detected bandwidth or cutoff, transition width, roll-off slope, Brickwall Score, cutoff stability, high-frequency occupancy, estimated source class and a plain-language explanation.
  • Focused output: normal files stay in summary counts and are omitted from the actionable list and log. A completed or stopped scan writes Audio Authenticity Analyzer.txt when log creation is enabled; only Review, Likely and failed items are listed in detail.
  • Non-destructive analysis: the analyzer never modifies audio files. Results are technical estimates, not absolute proof of a recording’s history.

Drag files from Finder and start work immediately.

Repair / Convert accepts file drops directly in its queue area. You can add one file, several files or CUE sheets, inspect the queue, select only the required items and convert with the current output profile.

Files and CUE sheets can also be dropped onto the Local Music Organizer application icon. A normal drop starts an automatic background conversion batch using the current Repair / Convert profile. Hold Option while dropping to open the first file in Audio Inspector instead of converting it.

For CUE albums, macOS may request access to the album folder containing the CUE sheet and its referenced audio files. The authorized root is remembered for later CUE files inside that folder. Multi-file CUE sheets are interpreted per referenced source file, so track ranges stay attached to the correct FILE entry.

Drop workflow

  1. Choose the required output profile and output folder.
  2. Drop files or a CUE sheet into Repair / Convert, or drop them onto the application icon.
  3. Use Analyze Queue when source details are uncertain.
  4. Convert only the selected queue items.
  5. Listen to and inspect every result before importing it into Music.app.

Careful file handling.

  • Conversion verifies the new output first. You can keep the source, move it to macOS Trash, or archive it in a dated LMO Converted Originals session that preserves the source path.
  • Playlist cleanup does not delete the physical audio file.
  • Diagnostics remain read-only.
  • Long tasks can be stopped.
  • Keep a current backup before maintenance.
  • Gain replacement uses a temporary candidate, structural verification and rollback before the original is committed.
  • Embedded artwork is checked with SHA-256 before and after gain or hidden-metadata remux operations.
  • Hidden metadata cleanup removes only explicitly selected removable tags and preserves core tags, lyrics, grouping and technical/container metadata.
  • The narrowly scoped recopy xattr cleanup removes only com.apple.lastuseddate#PS and preserves quarantine, FinderInfo, macl and Finder tags.
  • Naming & Tag Formatting scans are read-only. Physical filename renames are explicit, stay in the same folder with the same extension, verify the same Music.app track and artwork, and roll back when verification fails.
When support asks for logs

Record the problem from the beginning.

Enable the requested logging options before reproducing the issue, run the requested checks without applying fixes, and keep the same LMO session open until the requested scans and logs are complete.

  1. In Library Dashboard, enable Create Library Index Log before indexing.
  2. On scan pages that provide it, enable Create log files before the scan.
  3. In Setup, enable Write technical errors to a local log. This also exposes Music.app Diagnostics... for explicit support tests.
  4. For Startup State, quit Music.app first. The diagnostic then launches Music.app without sending Play and records several short state snapshots. For Track Flags, allow the bounded audit to continue through temporary pauses; difficult ranges may be retried in smaller pieces, and physical music folders are not traversed.
  5. After the tests finish, send the generated LMO text/log files from the selected log folder (commonly Desktop) together with the requested screenshots. Use Export Diagnostics only if support specifically asks for it.
