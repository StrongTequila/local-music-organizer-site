Built for offline collectors

For the libraries streaming forgot

The modern music world is moving toward subscriptions, cloud catalogs, and rented access. That works for many listeners, but there is another side of music collecting: people with offline libraries built carefully over years from CDs, downloads, rare releases, CUE albums, old formats, DJ archives, and personal folder structures.

Local Music Organizer was created from that side of the world. I am one of those users: I wanted a practical way to keep a large local Music.app library clean, playable, and under my control without turning everything into a subscription workflow.

This app is for people who still care about owning their files, keeping music available offline, and maintaining a real local collection. It focuses on the work that is easy to neglect and hard to do by hand: finding broken records, checking duplicates, repairing metadata, converting incompatible files, working with CUE sheets, and keeping Music.app useful for a library that has history.

Cleaner library, less wasted space

A well-maintained library can be smaller and easier to sync

Large local music collections often grow messy over time: duplicate records, repeated playlist entries, missing files, old converted copies, incompatible formats, oversized files, and albums kept in several versions. Local Music Organizer helps you review these problems before cleanup, so you can keep the library you actually use instead of carrying years of accidental clutter.

A properly cleaned and optimized offline library can take significantly less space on your Mac — and even more importantly, on an iPhone or iPad where storage is limited. The app is designed to help you find what is safe to review, repair, convert, or remove from playlists without blindly deleting your original archive files.

Built from a real library problem by an independent creator.

Local Music Organizer started as a personal tool, not as a generic software product. I built it because I was maintaining a large offline Music.app library collected over many years, and the usual manual checking became too slow and unreliable.

The problem was practical: repeated tracks, unclear playlist usage, old duplicates, missing artwork, inconsistent tags, suspicious file references, CUE albums, rare formats, and shuffle playlists that could start to feel repetitive. I needed one place to inspect the library, compare playlists, find where tracks were used, and review problems before changing anything.

The app was built around that real workflow: visibility first, safe review before cleanup, undo where possible, and no blind automatic deletion. It helped me bring order back to my own collection before I decided to make it available to other people with serious local music libraries.

That is why Local Music Organizer focuses on local files, Music.app playlists, clean metadata, backups, rare releases, and knowing exactly what will change before you press a button.

Warm once, then work faster.

Large Music.app libraries are slow when every tool has to ask Music.app for the same records again. Local Music Organizer is built around a cache-first workflow: warm full records and playlist usage first, optionally save the warmed cache between launches, then run repeated dashboards, comparisons, duplicate reviews, and File Search operations against prepared data.

The app now reports elapsed time for warm-up stages and completed scans, including separate timing for full records, playlist usage, and total warm-up time. Progress bars and status text are intended to show that long operations are alive instead of silently waiting.

Recommended workflow

  • Open Settings and enable Save warmed Music.app cache between launches if you want cache restore after relaunch.
  • Run Warm Cache with Include playlist usage for the fastest later File Search and playlist usage labels.
  • Wait for the cache status to show full records and playlist usage ready.
  • Run Library Dashboard, Playlist Compare, Library Duplicates, Track Usage, File Search, and related checks from warmed data.
  • Use Clear Cache after changing the Music.app library outside the app, then warm again.

Repair / Convert requirements.

Repair / Convert workflows may need optional external helper tools. The app can check what is installed and open Terminal-based installers for common helpers. Repair / Convert works with files on disk, CUE sheets, FFmpeg, and helper tools; it does not need Music.app playlist refresh or background Music cache while converting.

On a clean Mac, Homebrew may ask macOS to install Apple Command Line Tools. This is not the full Xcode app. It is Apple's smaller command-line developer tools package needed by Homebrew for some installations.

Original audio files should be preserved. Converted files should be reviewed before replacing references or removing anything from a library.

Recommended setup order

  1. Install Homebrew if Check Tools says brew is missing.
  2. Run Open Terminal Installer for FFmpeg and LAME.
  3. Run Install Old-School Helpers for xmp and WavPack tools.
  4. Run Install SACD Extract only if you use SACD ISO files.
  5. Use Copy OptimFROG Notes for manual OFR/OFS decoder setup.
  6. Use Add Files or Add CUE Sheet. Buttons and the drop zone accept drag and drop.
  7. Click Analyze Queue before conversion to refresh detected names, tags, ranges, codec/source info, and CUE parsing.
  8. Return to the app and click Check Tools again.

Built for messy real-world music libraries.

Large local collections are rarely clean. The same file may appear in many playlists, tags may be inconsistent, albums may be missing artwork, old imports may point to missing files, and quality can vary between versions. Local Music Organizer brings practical maintenance tools into one focused Mac app.

Scan and processing times can vary significantly depending on library size, the number of playlists and local files, Music.app response time, and disk speed. Very large libraries or slower external drives may take longer to analyze.

Library Dashboard

Creates a read-only overview of the Music.app library: records scanned, empty artists, low bitrate tracks, missing artwork, missing files, long tracks, codec/container information, storage clues, and suspicious records. Full-library dashboard scans require Early Access activation.

Music Snapshot Cache

Large libraries can be warmed before heavy work. The cache stores full Music records and playlist usage data; completed cache data can be restored after relaunch when saved cache is enabled.

Playlist Compare

Compares two playlists and shows tracks that appear in both. You can play A/B without bringing Music.app forward, stop playback from the app, inspect entries, edit tags, copy paths, or remove only the playlist entry from one side.

Playlist Duplicates

Finds duplicate entries inside one playlist. Removal affects the playlist entry only; it does not delete the audio file and does not delete the Music library record. Trial mode is limited to one playlist and up to 50 local tracks.

Library Duplicates

Finds Music.app library records pointing to the same local file or exact duplicate candidates. It helps identify unused duplicate records and protect playlist usage. Full-library duplicate analysis requires Early Access activation.

Track Usage

Searches for a track or file and shows playlist usage or physical file matches. Press Enter to run File Search. If playlist usage cache is ready, Used in playlists labels appear without a later usage scan. Playlist names are labels; the small Play button plays the matched Music.app entry.

Health Check

Scans selected playlists and library records for missing files, inaccessible paths, empty metadata, orphan physical files under a chosen root, and library records that need review.

Artwork Check

Finds tracks and albums with missing artwork. Artwork access is separated from lighter scans because it can be slower through Music.app.

Audio Quality Dashboard

Inspects bitrate, sample rate, file kind, duration, size, codec/container clues, missing files, long tracks, and suspicious records.

Quality Duplicates

Helps compare multiple versions of similar tracks and choose the better candidate by quality-related signals.

Audio Inspector

Opens a local audio file and shows technical information such as format, sample rate, bit depth, bitrate, channels, duration, size, raw afinfo data, and a spectrogram-style visual inspection.

Tag Editing

Visible Music.app records can be edited directly from the app. Supported tag changes update Music.app and can be undone. Editing actions require Early Access activation.

Repair / Convert workflows

Designed for mixed and old-school formats. Add Files and Add CUE Sheet support click or drag and drop. Multi-file CUE converts each referenced source as its own track; single-file CUE splits by INDEX 01. Analyze Queue refreshes names, tags, ranges, codec/source info, and CUE mode before Start Conversion.

File Maintenance

Helps reveal files in Finder, copy paths, check permissions, compare Music.app references with real files on disk, and understand whether library records point to accessible local media. File maintenance actions require Early Access activation.

Smart Shuffle Builder

Creates more natural shuffle-style lists by reducing repeated artist clusters, album blocks, and predictable patterns in large local collections.

Warm Cache and Auto Warm make large libraries practical.

Music.app automation can be slow with thousands of tracks and many playlists. Local Music Organizer can read expensive Music.app data once, reuse it across tools, and optionally restore a completed cache after relaunch.

  • Full Library Records Cache feeds Dashboard, Quality checks, Library Duplicates, File Maintenance, and fast library searches.
  • Playlist Usage Cache feeds Playlist Compare, Playlist Duplicates, Track Usage, File Search Used in playlists labels, Health Check, and usage protection.
  • Auto Warm Cache can start after launch idle time when enabled in Setup. It waits briefly so the app opens normally before cache work begins.
  • Include playlist usage lets File Search and Track Usage show playlist labels after cache without a later usage scan.
  • Save warmed Music.app cache between launches restores completed cache data after relaunch. Use Clear Cache after major Music.app changes.
  • Stop Cache stops cache warm-up after the current Music.app request returns. Repair / Convert skips Music.app cache because it works with files on disk and converter tools.

Safety-first cleanup.

The app is designed to make library maintenance understandable. It shows what it is about to change, avoids silent destructive actions, and keeps scan operations read-only unless you explicitly press an action button.

  • Scans do not delete audio files.
  • Playlist removal actions remove playlist entries, not physical audio files.
  • Tag edits are explicit user actions and are sent to Music.app.
  • Supported edits/removals have Undo and visible result refresh.
  • Log folders and reports help review completed scans. If you press Stop, the scan should stop immediately and no log file should be written for that stopped run.

Important responsibility note.

  • Keep a backup of important Music.app libraries before cleanup.
  • Use at your own responsibility when changing tags, playlist entries, or library records.
  • Very large libraries may take time to read from Music.app.
  • Automation permission for Music.app is required for Music.app operations.
  • Full Disk Access may be needed for file and folder checks.

Latest workflow behavior.

Recent Early Access builds focus on reducing confusing background work, making playback controls clearer, and keeping stopped scans quiet.

  • Track Usage / File Search: press Enter in the search field to run search. Physical-only results use Preview; cached Music.app matches use Play in Music. Used in playlists labels require playlist usage cache or Check Usage for Results.
  • Playback: Stop Music / Stop stops Music.app, Quick Look preview, and local preview playback without opening Music.app manually.
  • Stop behavior: pressing Stop makes the UI stop immediately. Stopped scans should not create a log file. Logs are for completed scans.
  • Repair / Convert: the queue owns Add Files, Add CUE Sheet, Analyze Queue, Start Conversion, and Clear Queue. It works with files and helper tools, not Music.app cache.
  • CUE: multi-file CUE and single-file CUE are handled differently and clearly reported in the queue summary.
