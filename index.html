Important for large libraries

Warm the cache before library analysis.

Music.app can be slow when an application asks it to read thousands of tracks and many playlists. The first cache warm-up may take a long time, especially with a very large collection. This is normal: Local Music Organizer is preparing the records and playlist relationships that its library tools will reuse.

Let the first warm-up finish. Once the cache is ready, Library Dashboard, Library Map, duplicate review, Playlist Compare, Track Usage, File Search and other repeated checks become much faster.

Enable saved cache restoration if you want the completed cache to be reused after relaunch. Clear and warm it again after substantial changes made directly in Music.app.

Mandatory after every library change: whenever tracks are added to Music.app or removed from Music.app, click Refresh Playlists and run Warm Cache again before using library-wide results. Warm Playlist Usage as well when playlist membership, File Search labels, Track Usage, Playlist Compare, Library Map, Playlist Duplicates or duplicate protection must reflect the current library.

Recommended first workflow

  1. Refresh Playlists.
  2. Open Setup and enable saved cache restoration if desired.
  3. Run Warm Cache.
  4. For complete File Search and playlist labels, enable Include playlist usage.
  5. Wait until full records and playlist usage show Ready.
  6. Then begin dashboards, comparisons and duplicate work.
Important distinction: cache warm-up accelerates Music.app library analysis and searches. Repair / Convert works directly with selected files and does not need the Music.app cache.

Built by a collector, for collectors.

I am a music collector and Music.app user with a large offline library accumulated over many years. Eventually it became total disorder: duplicate records, repeated playlist entries, missing artwork, inconsistent tags, broken references, several versions of the same album and rare formats scattered across different folders and disks.

I originally wrote Local Music Organizer for myself. I needed one place to understand the library before touching it: what was duplicated, where a track was used, which file was better, what was missing and what could be cleaned safely.

Conversion was another part of the same problem. No single converter handled every difficult source I owned. TAK, SACD ISO, DSD, DTS, AC3, CUE albums, tracker modules and other archival formats often required several tools and a fragile sequence of actions.

The program brought order back to my own collection and solved the practical problems I had lived with for years. Only then did I realize that it could also be useful to other people like me - people who still maintain serious offline music libraries and want control instead of automatic destructive cleanup.

Live Spectrum, interactive waveform and local player.

Open a physical audio file in an independent macOS player window without creating another Music.app record. The window combines real-time analysis, full-track navigation, transport controls and a cautious gain workflow.

Detailed analysis

  • 512 FFT bands on a logarithmic frequency scale with dBFS markings, peak trace and named frequency regions.
  • Full-track waveform with transient detail and a current-position cursor.
  • Click or drag across the waveform to seek; the lower progress bar is also draggable.
  • Technical cards report format, resolution, channels, duration, elapsed time, remaining time, progress, peak, RMS, headroom and clipping.
  • Fine, Balanced and Bold presets adjust analyzer density; bar thickness, gap, segmented LEDs, waveform and technical cards can be configured individually.

Transport and independent window

  • Pause keeps the current position. Stop ends playback and returns to 0:00 while keeping the loaded track and waveform. Eject clears the player.
  • The yellow window button minimizes to Dock. The red button hides the window without stopping playback.
  • When the hidden player is still playing, click the Local Music Organizer icon in Dock to restore it.
  • The player and main organizer window remain independent; clicking the player does not intentionally raise the main window.
  • Background conversion and gain processing do not intentionally close the Finder folder containing the source file.

Audio Authenticity Analyzer.

Batch-check the audio content behind a local Music.app library. The analyzer compares the declared codec, bitrate, sample rate and bit depth with measured spectral behavior, then surfaces only files that deserve review.

Library and playlist scanning

  • Scan the entire cached Music.app library or select one playlist.
  • Duplicate physical paths are analyzed once even when the track appears in several playlists.
  • MP3 and AAC files are checked for obvious disagreement between declared bitrate and observed bandwidth.
  • ALAC, FLAC, WAV, AIFF and other lossless files are checked for possible earlier MP3/AAC sources.
  • High-resolution files are checked for possible sample-rate upscaling and bit-depth padding.
  • The existing single-file drag-and-drop workflow remains available in Audio Inspector.

Conservative, explainable results

  • No obvious issue means the measured content is broadly consistent with the declared format.
  • Review recommended means one or more unusual indicators were found, but the evidence is not decisive.
  • Likely authenticity mismatch is reserved for a stronger combination of persistent cutoff, transition, occupancy and format-mismatch evidence.
  • Every flagged result includes confidence, detected cutoff, estimated source class and a plain-language explanation.
  • The analyzer never changes audio files. Results are technical estimates, not absolute proof of a file's history.

Scan results

Filter the results, open a flagged item in the single-file inspector, reveal it in Finder or copy its path.

Detailed reasoning

See the current codec and resolution, detected bandwidth, estimated source, confidence and the reason the track was flagged.

TXT

Desktop report

When log creation is enabled, the completed or stopped scan writes Audio Authenticity Analyzer.txt to the Desktop. The detailed list contains only Review, Likely and failed items; normal tracks appear only in the summary counts.

Drag files from Finder and start work immediately.

Repair / Convert accepts file drops directly in its queue area. You can add one file, several files or CUE sheets, inspect the queue, select only the required items and convert with the current output profile.

Files and CUE sheets can also be dropped onto the Local Music Organizer application icon. A normal drop starts an automatic background conversion batch using the current Repair / Convert profile. Hold Option while dropping to open the first file in Audio Inspector instead of converting it.

For CUE albums, macOS may request access to the album folder containing both the CUE sheet and its referenced audio file. The authorized root is remembered for later CUE files inside that folder.

Drop workflow

  1. Choose the required output profile and output folder.
  2. Drop files or a CUE sheet into Repair / Convert, or drop them onto the application icon.
  3. Use Analyze Queue when source details are uncertain.
  4. Convert only the selected queue items.
  5. Listen to and inspect every result before importing it into Music.app.
Important: Repair / Convert works directly with local files and does not require the Music.app cache.

Careful file handling.

  • Ordinary conversion writes new output files.
  • Playlist cleanup does not delete the physical audio file.
  • Diagnostics remain read-only.
  • Long tasks can be stopped.
  • Keep a current backup before maintenance.
  • Gain replacement uses a temporary candidate, structural verification and rollback before the original is committed.
  • Embedded artwork is checked with SHA-256 before and after gain or hidden-metadata remux operations.
  • Hidden metadata cleanup removes only explicitly selected removable tags and preserves core tags, lyrics, grouping and technical/container metadata.
  • The narrowly scoped recopy xattr cleanup removes only com.apple.lastuseddate#PS and preserves quarantine, FinderInfo, macl and Finder tags.
