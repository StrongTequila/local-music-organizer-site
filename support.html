First launch

You can use the ORIGINAL, CLASSIC and GLASS players without starting the trial or purchasing the Full Version. To use organizer tools, activate the limited three-day trial or unlock the Full Version. Open Setup and allow Music.app Automation access when macOS asks. macOS may separately ask for Music and Media Library permission for read-only Music.app metadata and file-location indexing through the system framework. If you denied it, open System Settings > Privacy & Security > Media & Apple Music and enable Local Music Organizer if it appears. Folder access is a third, separate permission granted through the system picker. When working with a Music.app library, build the Library Index, ideally with Include playlist usage enabled on the first full build.

Three-day trial, free players and Restore Purchases

The trial runs for three days. Each diagnostic/search tool permanently reserves up to 10 eligible actionable records or results; scans can still count further findings, but their individual details and actions remain restricted. The same reservations stay assigned across rescans, filter changes, selected playlists, cleared queues and app restarts. Selected-file tools normally reserve up to 10 distinct eligible files per tool. Removing a file or result does not free its slot.

Single File Audio Inspector and Album DR share one 10-physical-file allowance. Audio Gain has its own allowance of 10 distinct source files for analysis and explicit gain adjustment. An album with more tracks than the remaining permitted files cannot be reported as a complete Album DR. Repair / Convert permits 10 output-track conversion starts across the entire trial, including retries or reconverting the same track. Shuffle Builder allows one completed Create operation in the entire trial, not one per playlist. Preview does not consume that allowance. ORIGINAL, CLASSIC and GLASS playback remains free without a time limit, including after the organizer trial ends.

The trial does not renew automatically or charge you. The Full Version is a one-time Mac App Store in-app purchase, not a subscription. If you already purchased it, open the purchase/unlock screen and choose Restore Purchases while signed in with the same Apple Account used for the original purchase. If restoration is unsuccessful, contact support with the app version/build and the message shown; never send your Apple Account password.

Players on smaller MacBook screens

ORIGINAL, CLASSIC and GLASS share local playback and can use compact layouts. On smaller MacBook displays, press Escape to leave the player's fullscreen presentation if the macOS menu bar overlaps the standard window controls.

Music.app and standalone files

Library-wide organization tools work with Music.app records and LMO's saved Library Index. Audio Inspector, local playback, Repair / Convert, and supported physical-file workflows can also work directly with physically available local audio files. Single-file Audio Inspector includes authenticity evidence for the selected file, while the batch Audio Authenticity Analyzer uses the saved Library Index or an indexed playlist. Apple Music subscription content, cloud-only/online-only files and streaming audio are outside the supported local-file workflow.

Files and output folders

Add files and choose folders through the macOS system picker. If a file-based tool needs access to another physically available local or external location, macOS may ask you to select the containing folder. LMO can save that permission for reuse by its file tools and shows the saved location in Setup. The red offline warning for a saved location can be muted without disabling its saved access; Forget removes only LMO's saved permission/bookmark and does not delete files or Music.app records. If a disk or folder moved, choose it again. Network and NAS workflows have not been validated as a supported release workflow and are outside the documented scope; use physically available local files through normal macOS paths.

Why Audio Gain may ask for a folder after analyzing: reading or measuring a file is not the same as having permission to write beside it. Before applying Gain, LMO checks that it can create a temporary output next to every original. If a parent folder is not already writable, macOS asks you to authorize that exact folder before processing begins. For files in several restricted folders, you may see separate requests. Choose the requested source folder; cancelling or denying access stops the batch before originals are modified. Analyzing alone never rewrites a file.

Notifications

Setup contains two independent notification choices. Notify when procedures finish can report completed LMO procedures through macOS. Notify about incomplete newly added albums is off by default. When enabled, LMO uses an already complete Full Library Records index as a baseline, performs a lightweight Music.app identity check when new records are detected, and checks only the affected Artist — Album releases for missing tracks, missing discs or conflicting Track / Disc totals. This watcher does not require Automatic Library Index to be enabled, and it does not modify Music.app metadata or physical files. If tracks are removed and later imported again, that genuine new import is checked again even when the resulting album warning is textually the same as an earlier warning.

Library Index

On first use, open Library Dashboard, leave Include playlist usage enabled and click Build / Refresh Library Index. The saved Library Index is restored after relaunch and large results load in pages. After adding, replacing or removing a few tracks, use Refresh Music Changes. After changing one already indexed playlist, choose it and use Refresh Selected Playlist; use Index Selected Playlist when that playlist has not yet been indexed. A full rebuild is not required after every launch.

Normal startup does not launch Music.app. LMO restores the saved SQLite Library Index and can apply a small physical-change catch-up from the macOS FSEvents journal without opening Music.app or rescanning the whole collection. Automatic Library Index also waits while Music.app is closed and continues only after Music.app is already running. Explicit user-triggered Music-backed actions, including manual Library Index, Refresh Music Changes and Music.app Diagnostics, may launch Music.app when needed.

On an extremely large library, full Music.app records can be ready before all playlist-membership rows. LMO labels that playlist usage as partial instead of pretending the snapshot is complete. Use Index Playlist Usage or Index Selected Playlist to extend coverage. Do not clear the Saved Library Index merely because playlist usage is partial; the available full records remain useful.

Health Check

Health Check is read-only until you choose an explicit action. A Missing file means a Music.app record still exists but its saved local path is unavailable. An Orphan physical file is a readable file whose exact path is not represented by the saved Music.app library. These are different conditions: if an orphan is actually the replacement location for a Missing record, relink the existing Music.app record instead of importing a duplicate.

Repair Local Link... relinks one existing Music.app Persistent ID to a chosen file. Relink This Folder... maps the missing record's old parent folder to a replacement folder, previews exact relative-path matches and relinks the existing records; LMO does not move, copy, rename or delete the physical audio files. Remove Missing Record... removes only the exact live Music.app record after confirmation and verification, then synchronizes LMO's caches/index so stale missing state does not reappear.

For a genuine orphan import, LMO live-checks the exact physical path immediately before the Music.app action. An existing exact-path record is reused instead of creating a duplicate. The verified record can be added to several selected existing playlists and one optional new playlist.

Check Album Completeness (Track / Disc totals) is a read-only live Music.app check that reports missing numbered positions, missing discs or conflicting totals without querying the Internet or guessing titles. Find Track / Disc Numbering is a separate optional discovery scan. Its cleanup action targets only Track Number, Track Count, Disc Number and Disc Count. LMO verifies the live record before and after the write and restores exact pre-cleanup editable protected metadata if Music.app changes it during the numbering write; Persistent ID, location and artwork count remain fail-closed safety boundaries.

Quality Duplicates and A/B Compare

Quality Duplicates finds same-song candidates that point to different physical files so you can review which version you actually want to keep. Treat the result as evidence, not an automatic cleanup instruction: compare the file paths, playlist usage and technical facts before removing anything.

There are two ways to open A/B Compare. Use A/B Compare... on a Quality Duplicates result group to open two different physical files already selected from that group. Or click Manual A/B Compare... in the Quality Duplicates toolbar to start with empty Version A and Version B, then select two authorized, readable local files using Browse...; this does not require any Music.app playlist scan or duplicate result. Browse can also replace either file when comparing a found group.

Both methods open the same playback-only window. Choose the passage with Start and Loop, then use A and B for instant listening comparison. Loudness Match applies temporary playback gain only; it does not normalize or rewrite either source file.

B offset shifts only Version B's comparison start point by milliseconds. Use the slider for coarse alignment and the ±10 / ±100 controls for fine adjustment when two masters have slightly different lead-ins or edits. It does not time-stretch, resample or modify the file.

The live spectrum can show Bars or Lines and can display A+B, A only or B only. Peak, RMS, dominant frequency, LUFS, temporary Gain and the LISTENING marker help you correlate what you hear with measurable differences. The graph is comparison evidence, not a score and not a verdict that one master is automatically better. Any playlist removal, Music.app record change or physical-file cleanup remains a separate explicit action.

How to read scan results

A scan count is a review count, not an instruction to clean everything. A large hidden-tag count can be normal in a large collection. Review representative rows and the exact field names or technical evidence before applying any change.

Hidden Audio Tags and Finder Metadata

Scan Hidden Audio Tags reuses saved SQLite probe results for unchanged files when possible. Full Verify Tags deliberately rescans the physical files and can be slower. The resulting cards show exact embedded field names and values. Choose one or more tag-name groups or individual file fields before Clean Selected Hidden Tags; group selection applies to the full scan, not only displayed cards. Encoder and physically removable Copyright fields are separate explicit opt-ins. When File Maintenance verifies a physical M4A ©too atom, it also shows a separate M4A Encoded with section with its own reviewed removal action; that action does not alter MP3 stream headers, artwork or unrelated tags. Music.app-only Copyright is not changed by this tool: a previously imported Copyright value can remain visible after the physical field is removed. The separate M4A ©too action does not guarantee removal of encoder information already stored by Music.app, and MP3 MPEG/LAME gapless information is not cleared. Publisher, label, license, meaningful lyrics, artwork, core music fields and unsupported fields remain protected unless a particular physically supported field is explicitly eligible. On supported MP3 and M4A-family files, edits are verified and do not re-encode audio. A failed candidate is rolled back, but successful removal is permanent and cannot be restored using Undo Last Change. Use copies if you may need the original embedded metadata. See the interactive File Maintenance process.

Scan Audio Permissions and Full Verify Permissions inspect permissions before the separate reviewed Normalize 755→644 operation. Scan Finder Metadata is distinct from embedded audio tags: an allow-listed last-used Finder attribute may be selectively removed or, for supported 16-byte values, changed through reviewed date or raw-hex editing while unknown or protected attributes remain untouched. Neither scanning action modifies files.

Naming & Tag Formatting

In File Maintenance, Scan Naming & Tags is the single current toolbar action for this read-only scan. It checks repeated spaces and spacing around round parentheses in Music.app Title / Artist / Album and local filenames. Review one row or batch-fix selected issues only when you intend to make a change. Safe physical filename renaming keeps the same folder and extension, verifies the same Music.app track and artwork, and rolls back if verification fails. After a successful tag or filename change, LMO refreshes affected Music.app file information so Dashboard technical facts stay current.

Outdated Music.app file information

If Deep Dashboard shows Music.app info outdated, select that card to isolate the affected tracks. Refresh Music.app Info asks Music.app to reread the actual local file and verifies the result. LMO does not convert, move, delete or rewrite the audio file, and protected tag/artwork fields are checked for unexpected changes. When logging is enabled, the refresh history is written to the selected log folder.

Music.app Diagnostics

In Setup, enable Write technical errors to a local log to expose Music.app Diagnostics.... These are explicit read-only support tests: they do not edit Music.app tracks, playlists, metadata, artwork, audio files or the Saved Library Index, and they do not issue a Play command.

  • Startup State: quit Music.app first. LMO verifies that it is not running, launches it without Play, and records several short player-state snapshots over roughly ten seconds. A very large library that is still loading can be reported as not ready rather than blocking the diagnostic.
  • Track Flags: reads Music.app in bounded ranges and reports non-default playback-related flags plus storage-volume totals. A difficult range can be retried in smaller pieces, so the progress counter may pause and then continue. It does not traverse physical music folders and does not require Additional Folders.

Because these tests are explicit, Music.app opening during the diagnostic is expected. That alone does not mean an ordinary LMO launch opened Music.app.

When support asks for logs

  1. Before reproducing the issue, enable Create Library Index Log in Library Dashboard when the test involves indexing.
  2. Enable Create log files on the scan page when that option is available.
  3. In Setup, enable Write technical errors to a local log.
  4. Run the requested test without applying fixes unless support specifically asks for them. For Track Flags, send the final or partial log and include the last processed count; a temporarily stationary progress counter is less useful than the log.
  5. When the requested tests finish, send the generated LMO text/log files from the selected log folder (commonly Desktop), plus any requested screenshots. Use Export Diagnostics only if support specifically asks for it.

Audio Inspector and Authenticity Analyzer

Audio Inspector works directly with a standalone local file and does not need the Music.app Library Index. It shows codec/container family, channels, sample rate, bit depth, bitrate, duration and file size, plus the authenticity assessment, a dB-scale spectrogram and raw afinfo technical output. The static Inspector does not show a waveform; the interactive full-track waveform belongs to Live Spectrum.

Audio Inspector > Audio Authenticity Analyzer can scan the saved library or one selected playlist; use Single File mode for an individual file. Normal files are omitted from its actionable list; Review, Likely and failed items remain visible and can be written to the local report.

Dynamic Range (DR) analysis

In Audio Inspector > Single File, enable optional Full-track DR analysis when you want detailed loudness and dynamics measurements. It is off by default so regular format and spectrogram inspection stays fast. Full-track analysis reports TT-style DR (using three-second blocks), integrated loudness in LUFS, Loudness Range (LRA), sample peak in dBFS and an estimated 4× true peak in dBTP. DR is not available for tracks shorter than ten seconds; LRA may be omitted for recordings under one minute. The estimated true peak is not a certified laboratory measurement, and a DR number alone cannot establish which mastering sounds better.

Audio Inspector > Album DR analyzes an exact Music.app Artist — Album from the saved Library Index or supported audio files immediately inside a selected local album folder (not nested subfolders). The album selector searches the entire saved Music.app album index and pages through 50 albums at a time with Previous 50 / Next 50. Progress and available per-track metrics are shown as the scan proceeds. A complete album DR is displayed only if every track is analyzed; locked, failed or incomplete results are not presented as a full-album score. Single File and Album DR share the same 10-file trial allowance. Both modes are read-only: they do not retag, convert or adjust your audio.

See the illustrated DR overview and the User Guide for examples.

Editing Music.app tags

Supported tags can be edited manually from visible result cards. Nothing changes until Save to Music is used; after saving, the supported fields are written to the exact Music.app record. Undo Last Change restores the values from the most recent supported tag edit.

Clear All Comments

Clear All Comments changes only the Music.app Comments field for the matching records. LMO verifies the live Music.app value, updates the Saved Library Index so an older cached comment cannot reappear, and records Undo data only for comments that were actually present immediately before the operation. It does not rename or rewrite the physical audio files.

Conversion

Conversion and Audio Gain are separate choices inside Repair / Convert: selecting a conversion profile does not change the Audio Gain batch settings, and using the player's temporary Playback Gain does not rewrite the source.

Conversion engines are built in. Do not install Homebrew or separate codecs. Batch Normalize can review 48 kHz and high-bit-depth lossless files from Library Dashboard. After successful verification, choose Keep original, Move original to Trash, or Move original to LMO Backup Folder. A CUE sheet may ask for access to the folder containing its referenced WAV, FLAC or other source audio; regular Add Files and Drag & Drop do not request extra access when the selected file is already permitted. Opening files or CUE sheets from Finder or dropping them on the application/Dock icon stages them in Repair / Convert but does not start conversion. Review the queue and output settings, then press Start Conversion. Holding Option while opening or dropping sends the first file to Audio Inspector instead. For a problem, include the source format, chosen output profile and the Queue Report when relevant. Queue Report is informational and does not start conversion.

Audio Gain — individual tracks and albums

Open Repair / Convert > Audio Gain to work with individual local audio files, a folder of audio files, or an exact Music.app Artist — Album from the saved Library Index. Load Music.app Albums searches all saved albums; browse 50 at a time with Previous 50 / Next 50, or search by artist or album title. Use Analyze Gain first to measure tracks without changing them. The per-file results include integrated LUFS, LRA, DR when measurable, sample peaks and estimated 4× true peaks. Dragging files into Audio Gain does not automatically start rewriting them.

Auto Increase finds one safe positive gain for the entire selection, using measured peak headroom. Auto Decrease calculates one common attenuation for an overly loud selection, toward a lower integrated loudness; it does not boost quiet albums. Manual uses the same chosen dB adjustment for every selected file. All three modes preserve relative loudness between tracks within a batch; they do not normalize each track independently. Increasing too far risks clipping, while reducing gain on a heavily limited recording makes it quieter without restoring lost dynamics.

Review clipping and re-encoding warnings before explicitly confirming Apply to Originals…. LMO verifies folder write access first, creates and checks temporary outputs, verifies the applied gain and checks embedded artwork and applicable lossless bit depth before replacing originals. Progress and per-file success/failure remain visible inside the app. The optional Create detailed log files (Desktop) setting saves one consolidated log for the batch. The ORIGINAL player retains separate quick temporary Playback Gain (Auto for quiet tracks) and its single-file Apply to Original File action. Quick Auto targets a near −1 dBFS peak, whereas Batch Audio Gain analyzes full tracks and considers LUFS, LRA, DR and true-peak headroom; suggested gains may differ. During the trial, Audio Gain can operate on its 10 permanently reserved distinct physical files.

See the illustrated Audio Gain walkthrough. For a failed batch, send the visible error and, if enabled, the consolidated Desktop Gain log with your support request.

Include with a support request

  • macOS version and Mac model.
  • Application version and build number.
  • Exact source format and output profile.
  • The visible error and relevant application log.
  • Whether the file is local, external or on a network volume.
