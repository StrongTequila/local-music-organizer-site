First launch

Start the free 3-day trial from the access screen, then follow Setup and allow Automation access when macOS asks for permission to communicate with Music.app. The trial provides full access, does not renew and creates no automatic charge.

Music.app and standalone files

Library organization tools use the locally stored Music.app library. Audio inspection, authenticity analysis, playback, repair and conversion can also be used with standalone files opened from Finder or added by drag and drop. An Apple Music streaming subscription is not required.

Files and output folders

Add files and choose folders through the macOS system picker. If a disk or folder moved, choose it again. Network and NAS workflows have not been fully validated; test with copies before relying on them for maintenance or conversion.

Library Index

On first use, open Library Dashboard, leave Include playlist usage enabled and click Build / Refresh Library Index. The saved Library Index is restored after relaunch and large results load in pages. After adding, replacing or removing a few tracks, use Refresh Music Changes. After changing only one playlist, choose it and use Index Selected Playlist. A full rebuild is not required after every launch.

Normal startup does not launch Music.app. LMO restores the saved SQLite Library Index and can apply a small physical-change catch-up from the macOS FSEvents journal without opening Music.app or rescanning the whole collection. Automatic Library Index also waits while Music.app is closed and continues only after Music.app is already running. Explicit user-triggered Music-backed actions, including manual Library Index, Refresh Music Changes and Music.app Diagnostics, may launch Music.app when needed.

On an extremely large library, full Music.app records can be ready before all playlist-membership rows. LMO labels that playlist usage as partial instead of pretending the snapshot is complete. Use Index Playlist Usage or Index Selected Playlist to extend coverage. Do not clear the Saved Library Index merely because playlist usage is partial; the available full records remain useful.

How to read scan results

A scan count is a review count, not an instruction to clean everything. A large hidden-tag count can be normal in a large collection. Review representative rows and the exact field names or technical evidence before applying any change.

Hidden Audio Tags and Finder Metadata

Scan Hidden Audio Tags reuses saved SQLite probe results for unchanged files and reads only new or modified files when possible. Use Full Verify Tags only when you deliberately want every file checked again; it is slower by design. Clean Selected Hidden Tags begins only after explicit selection and preserves review-only fields such as publisher, label, copyright and license while verifying the rebuilt file and artwork.

Scan Finder Metadata is separate from embedded audio tags. Cleanup is deliberately narrow: only allow-listed Finder metadata is actionable, while unknown, protected, audio, artwork and embedded music metadata remains read-only.

Naming & Tag Formatting

In File Maintenance, Scan Naming & Tag Formatting is read-only. It checks repeated spaces and spacing around round parentheses in Music.app Title / Artist / Album and local filenames. Review one row or batch-fix selected issues only when you intend to make a change. Safe physical filename renaming keeps the same folder and extension, verifies the same Music.app track and artwork, and rolls back if verification fails. After a successful tag or filename change, LMO refreshes the affected Music.app file information so Dashboard technical facts stay current.

Outdated Music.app file information

If Deep Dashboard shows Music.app info outdated, select that card to isolate the affected tracks. Refresh Music.app Info asks Music.app to reread the actual local file and verifies the result. LMO does not convert, move, delete or rewrite the audio file, and protected tag/artwork fields are checked for unexpected changes. When logging is enabled, the refresh history is written to the selected log folder.

Music.app Diagnostics

In Setup, enable Write technical errors to a local log to expose Music.app Diagnostics.... These are explicit read-only support tests: they do not edit Music.app tracks, playlists, metadata, artwork, audio files or the Saved Library Index, and they do not issue a Play command.

  • Startup State: quit Music.app first. LMO verifies that it is not running, launches it without Play, and records several short player-state snapshots over roughly ten seconds. A very large library that is still loading can be reported as not ready rather than blocking the diagnostic.
  • Track Flags: reads Music.app in bounded ranges and reports non-default playback-related flags plus storage-volume totals. A difficult range can be retried in smaller pieces, so the progress counter may pause and then continue. It does not traverse physical music folders and does not require Additional Folders.

Because these tests are explicit, Music.app opening during the diagnostic is expected. That alone does not mean an ordinary LMO launch opened Music.app.

When support asks for logs

  1. Before reproducing the issue, enable Create Library Index Log in Library Dashboard when the test involves indexing.
  2. Enable Create log files on the scan page when that option is available.
  3. In Setup, enable Write technical errors to a local log.
  4. Run the requested test without applying fixes unless support specifically asks for them. For Track Flags, send the final or partial log and include the last processed count; a temporarily stationary progress counter is less useful than the log.
  5. When the requested tests finish, send the generated LMO text/log files from the selected log folder (commonly Desktop), plus any requested screenshots. Use Export Diagnostics only if support specifically asks for it.

Audio Inspector and Authenticity Analyzer

Audio Inspector works directly with a standalone local file and does not need the Music.app Library Index. It shows codec/container family, channels, sample rate, bit depth, bitrate, duration and file size, plus the authenticity assessment, a dB-scale spectrogram and raw afinfo technical output. The static Inspector does not show a waveform; the interactive full-track waveform belongs to Live Spectrum.

Audio Authenticity Analyzer can scan the saved library, one selected playlist or an individual file. Normal files are omitted from its actionable list; Review, Likely and failed items remain visible and can be written to the local report.

Editing Music.app tags

Supported tags can be edited manually from visible result cards. Changes appear in Music.app immediately. Undo Last Change restores the values from the most recent tag edit.

Clear All Comments

Clear All Comments changes only the Music.app Comments field for the matching records. LMO verifies the live Music.app value, updates the Saved Library Index so an older cached comment cannot reappear, and records Undo data only for comments that were actually present immediately before the operation. It does not rename or rewrite the physical audio files.

Conversion

Conversion engines are built in. Do not install Homebrew or separate codecs. Batch Normalize can review 48 kHz and high-bit-depth lossless files from Library Dashboard. After successful verification, choose Keep original, Move original to Trash, or Move original to LMO Backup Folder. A CUE sheet may ask for access to the folder containing its referenced WAV, FLAC or other source audio; regular Add Files and Drag & Drop do not request extra access when the selected file is already permitted. For a problem, include the source format, chosen output profile and queue report.

Include with a support request

  • macOS version and Mac model.
  • Application version and build number.
  • Exact source format and output profile.
  • The visible error and relevant application log.
  • Whether the file is local, external or on a network volume.
